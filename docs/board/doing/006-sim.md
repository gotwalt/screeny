## Goal

A host program that is indistinguishable from the device on the network, so senders
can be developed and tested with no hardware, and so we have a second, independent
implementation of the receiver side of `docs/design/protocol-v1.md` to shake out spec
ambiguities before the firmware (card 008) implements the same thing.

## Context

- Spec: `docs/design/protocol-v1.md`. Architecture: `docs/design/architecture.md`.
- Use `crates/proto` (`screeny-proto`, see its README) for ALL parsing, building and
  decoding. If you find yourself re-implementing wire logic, it belongs in proto - add
  it there (narrowly) and say so in your report.
- The receive rules are in spec section 3.3 (drain, newest wins, seq handling), 6
  (control ops, telemetry, piggybacked `STATS_REQ` replies), 7 (source lock, idle).
  Implement them as written; where the spec is ambiguous, pick, document, and fix the
  spec text in your branch.
- Panel look: round LED dots on black with gaps, sRGB -> linear -> 64 levels -> back
  (see `docs/design/generative-art-brief.md` section 5 "Build a faithful preview").

## Deliverables

`crates/sim` (package `screeny-sim`, binary `screeny-sim`):

- Library: `SimDevice` that binds frame + control UDP ports (defaults 49374/49375, but
  configurable and able to bind port 0 for tests), runs the receive state machine,
  exposes the current displayed frame, counters and events through a handle. This is
  what integration tests drive.
- Binary, windowed mode (default): LED-dot rendering at >= 12x, title/overlay with fps
  shown, codec of last frame, bytes/frame, drops by cause, active source. Pick a
  window crate that builds cleanly on macOS arm64 (`minifb` or `pixels`+`winit`);
  keep it simple.
- Binary, `--headless`: no window; logs stats once a second; `--dump-dir` writes every
  Nth displayed frame as PNG; `--exit-after SECS`.
- mDNS: advertises `_screeny._udp` with the spec's TXT keys using the `mdns-sd` crate,
  instance name `screeny-sim` (configurable), so it never collides with the real
  device (`screeny`). `--no-mdns` flag for tests.
- Fault injection for sender testing: `--drop PCT`, `--delay-ms MS`, `--decode-ms MS`
  (pretend the device is slow, so `frames_dropped_superseded` rises).
- Control ops: all of them. `SET_WIFI`/`REBOOT` are accepted and logged, not acted on.
  Brightness affects the rendering. Idle behaviour per spec (hold, then status screen).
- Tests: in-process sender (built directly on proto, a few lines) streaming every
  codec to a `SimDevice` on loopback and asserting the displayed frame is bit-exact;
  seq wrap, stale/duplicate rejection, source lock + takeover after timeout, `FINAL`
  releasing the lock, `STATS_REQ` reply contents, every control op, malformed packets
  counted not crashed.

## Acceptance

`cargo test -p screeny-sim` passes; `cargo run -p screeny-sim` shows a window that
displays frames sent by any spec-conforming sender; `dns-sd -B _screeny._udp` lists it.
